# 0 前言

在阅读nccl代码的时候遇到过很多template，在此记录一下，nccl的高级写法。

# 1 定义

比如使用容器(vector)的时候，可以定义不同类型的vector。例如`vector<int>`,`vector<string>`。模版大致分为：函数模版 and 类模版。他们的定义如下：

```python
template <typename type> ret-type func-name(parameter list)
{
	// 函数的主体
}

template <typename type> class class-name 
{
	// 函数的主体
}
```

# 2 nccl内使用

## 2.1 Primitives

nccl内有一个模版可以在编译的时候根据参数组合直接生成不同的通信算子版本。它的泛型定义如下：

```c++
template<typename T, typename RedOp, typename Fan, int Direct,
         int SlicePerChunk, int StepPerSlice, int Unroll, int P2p, int MultimemSrcs, int MultimemDsts, bool isNetOffload>
class Primitives<
    T, RedOp, Fan, Direct,
    ProtoSimple<SlicePerChunk, StepPerSlice, Unroll, MultimemSrcs, MultimemDsts>,
    P2p, isNetOffload
> {};
```

- 通过class得知这是一个类的模版，仔细一看这并不是主模版的定义，而是一个模版类的偏特化(partial specialization)。偏特化版本说的是：当 `Proto` 的类型恰好是 `ProtoSimple<SlicePerChunk, StepPerSlice, Unroll, MultimemSrcs, MultimemDsts>` 这种形式时，使用我这一份定义。
- 并且可以看到Primitives内还有一个`ProtoSimple<…>` 模版，这就是偏特化的条件。

其中在另一个文件可以看到主模版是:

```c++
template<typename T, typename RedOp, typename Fan, int Direct,
					typename Proto, int P2p, bool isNetOffload = false>
class Primitives;
```

 然后实际调用如下，等价于说生成一个类型是ProtoSimple的偏特化版本的Primitives出来，编译器实例化出对应的优化实现，然后构造一个对象 `prims` 用于执行对应通信操作。

```c++
using Proto = ProtoSimple<1, 1, COLL_UNROLL, 1, 1>;
Primitives<T, RedOp, FanSymmetric<1>, /*Direct=*/1, Proto, 0>
  prims(tid - tidEndGather, nThreadsReduce, &nvls->down, &nvls->down, NULL, NULL,
    work->redOpArg, 2 * Proto::MaxGroupWidth, 0, 0, work);
```
