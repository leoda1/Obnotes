# 一、Torch Profiler 怎么抓

vLLM 0.13.0 官方写得很明确：  
给 `vllm serve` 加 `--profiler-config`，其中 `profiler` 设成 `"torch"`，trace 目录用 `torch_profiler_dir`；trace 可用 Perfetto 打开。官方还提醒只发少量请求，并建议把 `VLLM_RPC_TIMEOUT` 设大，因为 stop 时 flush trace 可能很慢。

## A. MooncakeConnector 版本

### prefill
```
export VLLM_RPC_TIMEOUT=1800000  
export VLLM_MOONCAKE_BOOTSTRAP_PORT=8998  
  
CUDA_VISIBLE_DEVICES=0 \  
vllm serve $MODEL_NAME \  
  --host 0.0.0.0 \  
  --port 8100 \  
  --profiler-config '{  
    "profiler":"torch",  
    "torch_profiler_dir":"./torch_prefill_mooncake",  
    "torch_profiler_record_shapes":true,  
    "torch_profiler_with_memory":true,  
    "torch_profiler_with_stack":true  
  }' \  
  --kv-transfer-config '{"kv_connector":"MooncakeConnector","kv_role":"kv_producer"}'
```

### decode

```
CUDA_VISIBLE_DEVICES=1 \  
vllm serve $MODEL_NAME \  
  --host 0.0.0.0 \  
  --port 8200 \  
  --profiler-config '{  
    "profiler":"torch",  
    "torch_profiler_dir":"./torch_decode_mooncake",  
    "torch_profiler_record_shapes":true,  
    "torch_profiler_with_memory":true,  
    "torch_profiler_with_stack":true  
  }' \  
  --kv-transfer-config '{"kv_connector":"MooncakeConnector","kv_role":"kv_consumer"}'
```

### proxy

```
python tests/v1/kv_connector/nixl_integration/toy_proxy_server.py \  
  --prefiller-host localhost \  
  --prefiller-port 8100 \  
  --decoder-host localhost \  
  --decoder-port 8200
```

上面这些 role 和 proxy 路径都是 Mooncake 0.13.0 官方文档里的写法；Mooncake 还要求 prefiller 侧配置 `VLLM_MOONCAKE_BOOTSTRAP_PORT`。

## C. 开始/停止抓取

只要 server 开了 profiler，官方就支持用 profile API 控制抓取窗口。最干净的方式仍然是：

```
curl -X POST http://127.0.0.1:8100/start_profile  
curl -X POST http://127.0.0.1:8200/start_profile  
  
curl -X POST http://127.0.0.1:8000/v1/completions \  
  -H "Content-Type: application/json" \  
  -d '{  
    "model":"'"$MODEL_NAME"'",  
    "prompt":"Write a detailed explanation of PD disaggregation.",  
    "max_tokens":64,  
    "temperature":0  
  }'  
  
curl -X POST http://127.0.0.1:8100/stop_profile  
curl -X POST http://127.0.0.1:8200/stop_profile
```

如果你的 proxy 监听的是 NIXL 示例里的 `8192`，就把请求目标改成 `8192`。Torch profiler 的 trace 用 Perfetto 看。

# 二、Nsight Systems 怎么抓

官方 0.13.0 对 `nsys` 的建议是：

- `export VLLM_WORKER_MULTIPROC_METHOD=spawn`
- `nsys profile --trace-fork-before-exec=true --cuda-graph-trace=node`
- 对 server 再加  
    `--capture-range=cudaProfilerApi --capture-range-end repeat`
- 并在 `vllm serve` 上设 `--profiler-config.profiler cuda`。

## A. MooncakeConnector + nsys

### prefill

```
export VLLM_WORKER_MULTIPROC_METHOD=spawn  
export VLLM_MOONCAKE_BOOTSTRAP_PORT=8998  
  
CUDA_VISIBLE_DEVICES=0 \  
nsys profile \  
  -o mooncake_prefill \  
  --trace-fork-before-exec=true \  
  --cuda-graph-trace=node \  
  --capture-range=cudaProfilerApi \  
  --capture-range-end repeat \  
  vllm serve $MODEL_NAME \  
    --host 0.0.0.0 \  
    --port 8100 \  
    --profiler-config.profiler cuda \  
    --kv-transfer-config '{"kv_connector":"MooncakeConnector","kv_role":"kv_producer"}'
```

### decode

```
export VLLM_WORKER_MULTIPROC_METHOD=spawn  
CUDA_VISIBLE_DEVICES=1 \  
nsys profile \  
  -o mooncake_decode \  
  --trace-fork-before-exec=true \  
  --cuda-graph-trace=node \  
  --capture-range=cudaProfilerApi \  
  --capture-range-end repeat \  
  vllm serve $MODEL_NAME \  
    --host 0.0.0.0 \  
    --port 8200 \  
    --profiler-config.profiler cuda \  
    --kv-transfer-config '{"kv_connector":"MooncakeConnector","kv_role":"kv_consumer"}'
```

Mooncake 的不同点只在 connector 和 bootstrap 环境变量；`nsys` 的抓法本身不变。

# 三、Mooncake 和 NIXL 下，怎么理解你抓到的东西

## Mooncake

Mooncake 文档强调它走的是高性能缓存池 / RDMA / zero-copy 风格传输。对你来说，重点是看：

- prefill 侧：算完 KV 以后有没有明显停顿再发出去
- decode 侧：拿到 KV 前是否有空洞
- 如果多 NIC / 远端盘或远端内存体系参与，GPU 忙碌区和 CPU side thread 活动是否错位

Mooncake connector 本身还有后台 sender/receiver 线程实现，所以你在 trace 里更容易看到“GPU 计算没问题，但外围传输节奏不顺”的现象。这个方向从 Mooncake 文档和 API 描述都能看出来。

## NIXL

NIXL 文档明确说它是 **fully asynchronous send/receive**，并且底层通信主要依赖 UCX。分析时重点看：

- UCX 配置是否正确，否则 decode 侧可能会出现等待 KV 的空洞
- `--enforce-eager` 下是否更容易读到真实 kernel / API 节奏
- prefill / decode 两侧 trace 是否在同一个请求上对得齐

如果你看到 decode GPU 很闲，而 prefill 已经算完很久，通常优先怀疑：

1. side channel / handshake；
2. UCX 设备选择；
3. 请求在 proxy 到后端之间的路由时序。

# 四、我给你的实际建议

先用 **nsys**。  
因为它最容易看出：

- prefill 端是不是很快算完
- decode 端是不是在等 KV
- 两侧 GPU 时间线之间有没有明显断层

这对 Mooncake/NIXL 都比 torch profiler 更直观。

# 五、最容易踩的坑

### 1. 只 profile proxy

不够。  
真正干活的是 8100/8200 两个 `vllm serve`，proxy 只是转发。这个在 Mooncake/NIXL 两套用法里都一样。

### 2. NIXL 还在配 NCCL 的网卡变量

官方明确说 **NIXL 用 UCX，不看 NCCL 那套变量**。

### 3. Mooncake 忘了 bootstrap port

Mooncake 文档说 `VLLM_MOONCAKE_BOOTSTRAP_PORT` 是 prefiller 必需项。

### 4. 请求发太多

官方 profiling 文档明确建议只发少量请求，不然 trace 很大，stop flush 很慢。
