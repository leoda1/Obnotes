## optim

### 1. 双口网卡问题
背景: 在 b300 上验证发现，8 gpu 配 16 个 400g nic 时，会出现 redispatch(mooncake 的 fault tolerance逻辑)，而 pxn 我最开始假设为每个 gpu 用一个最近 pcie nic 来转发流量。当请求拿着tcp 传来的 target 的结构体后(preferred_hca字段内是 2 个 nic)，pxn 认为对端只有一个和我是可以发的 故流量进来 不知道选本地哪个网卡发 出现错误。

增加双口网卡支持，确定 pfc 得到有效解决，commit: 71b641d0de3c98f3616ce6e731d60915e4056a0d ✅ 2026-08-29

### 2. 每个 transfer engine的 pxn worker 效率低

背景：第一版设计时，我们的一个 pxn worker 需要兼顾把上层任务下来拆分后，丢到 relay buffer 内，还有负责 relay buffer 内的任务再丢给 rdma 搬走，还有对应这俩任务的结束时间的 pollcq和 update completed等等控制面操作，且每次扫一遍每个 lane，对每个 lane 内的 18 个 slots 都推进一格消耗一格，这么操作导致的任务提交和消耗都很慢。

sender 侧改为 2 个线程分别下 cudaMemcpyBatchAsync、submitToRdma，以及 poll 任务从一次 poll 一个改为 poll 一堆。性能确定达到 97%原生 ✅ 2026-08-29

### 3. 分析瓶颈(97->100%)

在日志内增加 lane 内每个 slots 状态，确定当前瓶颈在下nvlink操作被 sglang 阻塞。具体原因为多个 batch 操作会被 reshard 到上层的一个线程内，导致并发的 batch—WriteSync 操作少，然后下nvlink操作的并行度大打折扣。 ✅ 2026-08-30

发现 sglang 内单 decode 的时候即使每个 engine 有多个 thread 下 batch put 的操作，但是多线程的 reshard 是分给多个 decode 的。所以我调整为一个 d 的时候也能用多个 thread 下 transfer 的请求。（这个收益是明确为正的）。

### 4. 为什么原生的 mooncake 测试时候发现 rank0的流量会比别人多
因为GLM-5 是 MLA+DSA, sglang 侧 `is_mla_backend=True`:
- KV latent 复制 ×8（每 prefill rank → 全部 8 个 decode rank）；
- **DSA indexer state 只由 prefill CP rank0 发送**（`mooncake/conn.py:1216-1234`），×8 份。

又因为我们的开了 `MC_ENABLE_DEST_DEVICE_AFFINITY=1` 同名匹配 → 这些流量在 decode 侧**全部**从同名的 mlx5_000/001 进入；

```python
    def _get_dsa_cache_transfer_skip_flags(
        self, info: Optional[KVArgsRegisterInfo]
    ) -> Tuple[bool, bool]:
        skip_kv = False
        skip_state = False

        # Must be checked before the non-hybrid early return below, or every CP
        # rank re-sends the same state and we transfer it cp_size times over.
        # Prefill CP all-gathers before writing the pool, so every CP rank holds
        # the full state regardless of whether the pool is hybrid. We assume no
        # structure about the state rows, so we don't split them across CP ranks
        # -- just let rank 0 send the whole thing (unless layer split already
        # shards it per rank).
        if (
            self.attn_cp_size > 1
            and self.attn_cp_rank != 0
            and not get_parallel().enable_dsa_cache_layer_split
        ):
            skip_state = True

        if not self.is_hybrid_mla_backend:
            return skip_kv, skip_state

        if info is not None and self.attn_tp_size > info.dst_attn_tp_size:
            sub_rank = (self.kv_args.engine_rank % self.attn_tp_size) % (
                self.attn_tp_size // info.dst_attn_tp_size
            )
            if sub_rank != 0:
                skip_kv = True
                # Hybrid-MLA KV is replicated across these source ranks, but
                # TP-sharded state needs every rank for the aggregation path.

        return skip_kv, skip_state
```
